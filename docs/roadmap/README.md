## Recently completed (since the last sync)

Non-exhaustive highlights — see individual issue/PR history for full detail:

- Extracted FFXIV market/crafting and real-world stock market data into standalone, self-contained plugins under `plugins/` (issues #106, #109), plus a generic `contributePromptContext` hook (issue #108) so plugins inject chat-reply context without `server-routes.js` hardcoding each one by name. See [plugins/README.md](../../plugins/README.md).
- OpenAI-compatible API (`/v1/chat/completions`, `/v1/embeddings`, `/v1/models`) so external tools like Obsidian Copilot can talk to Mana directly (issue #95).
- Obsidian plugin (Mana Memory Sync) that pulls Mana's memory into a vault as linked notes (issue #89), plus setup-time Obsidian detection.
- Reorganized `node-bot/server.js`'s admin routes into focused capability modules under `node-bot/capabilities/`.
- Fish Speech (S1-mini) as Mana's default TTS provider, with inline reference-audio voice cloning and automatic gaming-mode device swap.
- Best-of-N self-voting inference, idle-triggered Dream Mode memory consolidation, and cross-session memory connections/entity tagging.
- Deep Research mode (multi-step, multi-source, cited report) with a UI entry point in `windows-launcher`.
- Silero VAD replaces the RMS-threshold live speech/silence detection in `windows-launcher`'s continuous-listening loop, with a graceful fallback if the model is unavailable (issue #135). See [issue-135-silero-vad.md](issue-135-silero-vad.md).
- `windows-launcher` UI overhaul: popup info bubbles, redesigned Doctor panel, startup loading screen, the Mana Crystal logo, a fuller Settings menu (Logs/Plugins), and a themed scrollbar -- brings it up to par with `desktop-client`'s recent reskin (issue #138). See [issue-138-windows-launcher-ui-overhaul.md](issue-138-windows-launcher-ui-overhaul.md).
- Procedural skills layer: a `node-bot/skills/` store for "how I did X last time" knowledge, separate from Dream Mode's factual memory -- cheap always-available index, full content loaded only on demand, idle-gated stale/archive pruning (issue #140). See [issue-140-skills-layer.md](issue-140-skills-layer.md).
- Issue #65 (Fish Audio S2 Pro TTS) closed as **no-go**: the RTX 5080 arrived, but S2 Pro's official requirement is 24GB VRAM (not the ~10GB weights-only estimate the issue was opened with), and the unofficial GGUF/`s2.cpp` route that does fit doesn't have solid streaming yet. S1-mini stays the TTS model; the actual low-latency goal moves to #331 above.
- Local model stack upgraded for the RTX 5080 (16GB): chat/quality moved from Qwen3-14B to **Qwen3.5-9B** (newer training generation scores higher on every directly comparable benchmark -- MMLU-Redux, GPQA-Diamond, C-Eval, IFEval -- at 5.68GB vs 9.00GB, not a size/quality trade-off), vision moved from Qwen2.5-VL-7B to Qwen3-VL-4B and then further to **Qwen3.5-9B** (see below), and fast/background moved from Qwen2.5-1.5B to **Qwen3-1.7B**. The coding profile was upgraded further: a **self-quantized Q4_K_M build of Qwen2.5-Coder-7B**, calibrated with a custom imatrix built from Mana's own codebase plus the user's other real projects (Python/TS-React/SQL/C++), replacing the generic community quant at the same size/VRAM cost. Side-by-side comparison against the generic quant: 3 wins/edges, 1 loss, 2 ties across 6 tasks, with one genuine correctness win (a React animation component) directly traceable to the custom calibration. See [coding_model_quantization.md](../coding_model_quantization.md) for the full pipeline, corpus composition, and comparison detail. All four swapped models were verified against their real production code path (`llama-server` + `/v1/chat/completions`, not just the raw CLI, which gave a false-positive "broken" result for Qwen3's default thinking-mode behavior before `--reasoning off` was confirmed working through the actual HTTP path).
- Chat and vision **consolidated onto one model** (Qwen3.5-9B), eliminating the model-swap latency between text and image use. This followed a real evaluation, not an assumption: a 5-prompt spot check between Qwen3-VL-4B and Gemma 4 E4B (candidate vision swap) showed a tie, but a proper benchmark run (real MMLU-Pro 168q + GSM8K 120q, self-scored at deployed Q4_K_M quant) showed Qwen3.5-9B beating Gemma 4 E4B by 11.3pts on MMLU-Pro and 3.3pts on GSM8K -- at which point it turned out Qwen3.5-9B is *also* natively multimodal (unlike Qwen3, which needed a separate `-VL` variant), tested it directly, and its vision quality beat both Qwen3-VL-4B and Gemma 4 E4B on the same screenshot tests. Net: one model, best-in-class on every metric tested, zero swap cost. See [vision_setup.md](../vision_setup.md) for the consolidation config (`LLAMA_VISION_MODEL`/`LLAMA_VISION_MMPROJ` pointed at the same file as `LLAMA_MODEL`). Native audio/video understanding by the LLM itself was explicitly *not* pursued -- see issue #439. (Speech in/out already works via a separate pipeline -- Whisper/Parakeet STT in, Fish Speech S1-mini TTS out -- neither of which routes audio through the LLM directly.)
- Qwen3.5-9B's chat+vision consolidation was re-validated against **gemma-4-12B-it** with a much larger, more comprehensive benchmark (560 MMLU-Pro questions across 11 categories + 400 GSM8K questions, same question set for both models, self-scored at deployed Q4_K_M quant): gemma-4-12B-it edged ahead on raw text benchmarks (68.9% vs 67.3% MMLU-Pro, 95.8% vs 94.2% GSM8K -- roughly +1.6pts each), but it **costs more VRAM** (~7.7-8GB resident vs Qwen3.5-9B's noticeably lighter footprint -- reducing context/parallel-slots barely moved it, so this looks like an architecture floor, not a tunable) **and its vision is broken** on Mana's current llama.cpp build: loading its `mmproj` (confirmed to exist, same source repo, correct file) corrupts generation entirely -- not just image requests, plain text-only completions too -- isolated to the `--mmproj` flag specifically (`--jinja` alone works fine). This is an upstream llama.cpp/Gemma-4 multimodal immaturity issue, not a Mana config problem. **Decision: stay on Qwen3.5-9B** -- the ~1.6pt text edge isn't worth losing a verified-working vision path and eating more VRAM. If llama.cpp's Gemma-4 multimodal support matures later, the benchmark harness and result data are kept at `tools/quantize-work/bench/` to re-run the comparison without redoing the setup work.
